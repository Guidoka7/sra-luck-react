## 3. `logs_alteracoes` — confirmado como fonte central de auditoria

Schema real: `id uuid pk`, `usuario text`, `acao text`, `entidade text`, `entidade_id uuid`,
`detalhes jsonb`, `created_at timestamptz` (índice `idx_logs_created_at desc`). RLS: policy única
`admin_full_access_logs` (`auth.role() = 'authenticated'`, todas as operações). Volume atual: 1153
linhas, cobrindo `boleto` (551), `clientes` (283), `datas_liberacao_financeira` (93), `datas` (83),
`solicitacoes_liberacao_financeira` (55), `notificacoes_cliente` (55), `agendamentos` (33).

**Decisão confirmada:** não criar `clientes_historico`. O histórico por cliente será uma
consulta/agregação sobre `logs_alteracoes` (`entidade_id = cliente.id` OR `detalhes->>'cliente_id' = cliente.id`,
já que para `entidade='boleto'` o `cliente_id` vive dentro de `detalhes`, não como coluna própria).

**Nota para melhoria futura (Fase 1, ainda não aplicada):** falta hoje um índice em `entidade_id`
— com 1153 linhas não há problema de performance ainda, mas a consulta por cliente vai fazer scan
completo até esse índice existir. Proposta aditiva para quando a Fase 1 for autorizada:
`CREATE INDEX IF NOT EXISTS idx_logs_entidade_id ON logs_alteracoes(entidade_id)`. Nenhum índice foi
criado agora — isto é apenas o registro da necessidade futura.
